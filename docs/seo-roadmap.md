# Роадмап SEO и доступности сайта для ИИ-поиска

Цель: индексируемый каталог Packera с постоянными адресами, достоверными предложениями и доступным HTML. Рекомендации ИИ и позиции поиска не гарантируются.

Основа: существующие Vue, Express, PostgreSQL и админка. Сохраняем дизайн, корзину, варианты товаров, цены и версионное сохранение. Публикация на продакшен согласуется отдельно. Браузерные проверки выполняет пользователь; разработчик проверяет связанные тесты, сборку и HTTP.

13 октября 2026 года по явному согласованию опубликован релиз `41d8507` на `https://packera.kz/`. Production-контейнер здоров. Публичные HTTPS-проверки подтвердили серверный HTML главной, товара, категории, задачи и KK-страницы, доступность ресурсов, правильные типы robots.txt/sitemap.xml, noindex админки, 401 сессии без авторизации и 404 неизвестной страницы. Sitemap содержит 159 уникальных адресов и проходит XML-парсер. Контрольные суммы основных полей 129 товаров, 16 категорий, 6 задач и одного баннера совпали до и после обновления. Резервные архивы сохранены только на сервере по решению владельца; предыдущий образ сохранён для отката. Ниже сохранены результаты локальной реализации каждого этапа до публикации; Search Console/Bing/журналы Cloudflare и браузерная проверка остаются непроверенными.

## 1. Техническая основа — реализовано локально

- Единый основной адрес `https://packera.kz/` в canonical и Open Graph; корректные метаданные главной и существующее изображение для предпросмотра.
- Постоянные перенаправления с известных альтернативных доменов; HTTPS за настроенным доверенным прокси. Локальные адреса работают без перенаправления на продакшен.
- Настоящий robots.txt. Не блокировать JS, CSS, фотографии и `/api/data`, от которого зависит текущая витрина.
- `X-Robots-Tag: noindex` для админки и API. Авторизация остаётся обязательной; robots.txt не является защитой.
- Главная и `/admin` продолжают открываться; неизвестные страницы и отсутствующие файлы возвращают 404, а не главную с кодом 200.
- Готовность: связанные HTTP-тесты, проверка метаданных, сборка; затем проверка после публикации. Sitemap пока не заявляется: формируется на этапе 5 по реальным страницам.

Проверено: два связанных теста, Vite-сборка, diff; локальные HTTP-ответы главной, админки, robots.txt, редиректов и 404. Публичный GET `/api/data` возвращает 200; запись без авторизации — 401. Проверка кода не выявила существенных замечаний. Браузер, DNS/TLS альтернативных доменов и правила Cloudflare не проверены; на продакшен этап не опубликован.

## 2. Страницы и адреса каталога — реализовано локально

- Постоянные URL `/product/id-<ID>`, `/catalog/id-<UUID>`, `/tasks/id-<ID>` используют существующие идентификаторы без миграций. ID кодируются; переименование не меняет адрес. Скрытые товары и удалённые объекты возвращают 404, неверный UUID категории также возвращает 404.
- Названия товаров, кнопки категорий/задач и соответствующие действия баннеров ведут на страницы. Прямые запросы получают метаданные конкретной записи из актуальной БД; canonical исключает параметры варианта. Тело страницы пока требует JavaScript.
- Страница товара повторно использует каталог: фотографии, описание, характеристики, все размеры, цену, количество и корзину. Выбор размера отражается в `?size=…`, заменяя текущую запись истории. Неизвестный размер удаляется из URL; фотографии других вариантов исключаются по существующей логике галереи.
- Добавлены обработка истории и восстановление прокрутки, сообщения недоступности данных и повторная загрузка для отдельных страниц. Корзина сохраняется между переходами внутри приложения; поведение при перезагрузке не менялось.

Проверено: 9 связанных тестов маршрутов, HTTP, метаданных и галереи; Vite-сборка; локальные ответы главной, админки, товара, категории, задачи и ошибок 404. Браузерные переходы, внешний вид, выбор размера и покупка в интерфейсе требуют пользовательской проверки; браузер не запускался. Публикации на продакшен не было. Серверный HTML содержимого и локализованные SEO-адреса остаются этапами 3 и 4.

## 3. Серверный HTML — реализовано локально

Реализовано: общее чтение согласованного снимка БД для API/SSR; серверная сборка существующих Vue-компонентов с изолированными данными запроса; передача того же снимка клиенту для гидратации; главная и страницы каталога с SSR без кеша HTML. Стили, API сохранения и расчёт корзины не менялись. Новые зависимости и миграции не добавлены.

- Серверный рендеринг публичной части на текущих Vue/Express. Один и тот же контент для посетителей и ботов; админка сохраняет текущую архитектуру.
- Общие данные из PostgreSQL, без отдельной копии каталога для SEO. Серверный HTML содержит предложение без JavaScript.
- Кеш и его обновление после сохранений; не допускать устаревших цен/наличия и расхождения разметки с видимым содержимым.
- Готовность: HTML товара содержит название, характеристики, цену и ссылки; после правок в админке данные обновляются, гидратация не ломает интерфейс.

Проверено: 11 связанных тестов рендеринга, реальных записей API в отдельной тестовой БД, маршрутов, метаданных, JSON-вставки и галереи; клиентская и серверная production-сборки; локальные HTTP-ответы с содержимым без JS. Проверены независимость одновременных запросов, цена выбранного варианта, обновление HTML после сохранения и 404 скрытых/удалённых товаров. Браузерная гидратация, внешний вид и клики не проверялись по договорённости; эту проверку выполняет пользователь. На момент завершения этапа начальный HTML был RU; локализованные SEO-адреса добавляются на этапе 4. Публикации на продакшен не было.

## 4. Содержание и структурированные данные — реализовано локально по подтверждённым данным

- Проверенные условия доставки, оплаты, контакты и сведения о продавце; текстовые характеристики товаров.
- Product/Offer/BreadcrumbList и сведения о магазине из реальных данных. Без выдуманных рейтингов, отзывов или остатков.
- RU/KK-адреса, lang и hreflang для действительно переведённых страниц. Не создавать дубли с фиктивными переводами.
- Готовность: разметка соответствует видимой странице; коммерческие условия подтверждены владельцем.

Реализовано: JSON-LD товаров с ценой выбранного/первого варианта, реальными фотографиями, описанием и характеристиками; навигация BreadcrumbList; Organization с названием, доменом, логотипом, общими с интерфейсом телефоном, адресом и описанием доставки, территорией обслуживания Казахстан. Сервер и SPA используют одно правило разметки; при изменении размера/страницы разметка обновляется. Не добавлены неподтверждённые остатки, артикулы, рейтинги и коммерческие условия.

Добавлены `/kk/` и `/kk/tasks/id-<ID>` по существующим переводам главного блока и задач. Начальный HTML и гидратация учитывают язык URL; RU-адреса сохранены. Пары имеют отдельные canonical, взаимные hreflang и корректный lang/locale. Неполные переводы не публикуются. Товары и категории пока открываются на RU; названия товаров в KK-витрине сохраняют исходный язык.

Владелец подтвердил: Алматы, ул. Ратушного, 78в; +7 707 944 00 55; вторник–воскресенье; рассрочка Kaspi/Halyk/Forte; доставка по всему Казахстану, по Алматы бесплатно от 70 000 ₸. Локальная витрина перезапущена с сохранённой БД. Браузерная гидратация, клики и внешний вид, Google Rich Results Test и опубликованные страницы не проверялись.

## 5. Индексация и контроль — техническая часть опубликована, поисковые кабинеты и журналы требуют доступа

- Автоматический sitemap по опубликованным каноническим страницам; актуальность после добавлений/удалений.
- Проверка Cloudflare для Googlebot, Bingbot и OAI-SearchBot по официальным правилам и журналам. Политика GPTBot (обучение) определяется отдельно от поискового обхода.
- Search Console и Bing Webmaster Tools, проверка индексации выборки URL, анализ реальных запросов, переходов и обращений покупателей.
- llms.txt не является обязательным условием появления в ИИ-поиске; добавлять только при понятной практической необходимости.
- Готовность: sitemap принят, страницы доступны ботам, есть базовые измерения для сравнения. Индексация и рост трафика требуют времени и не гарантируются техническими проверками.

Реализовано: динамический XML `/sitemap.xml` из актуального согласованного снимка БД; канонические RU-адреса главной, видимых товаров, категорий и задач, только доступные KK-версии главной/задач и взаимные XHTML-alternate ссылки. `robots.txt` содержит адрес карты. Карта не кешируется; скрытие/удаление записей и неполные переводы учитываются сразу. Параметры вариантов, админка/API и фиктивные даты обновления исключены. Новые зависимости и миграции не добавлены.

Публичная проверка 10 октября 2026, 18:58 UTC: `https://packera.kz/`, `/robots.txt` и `/sitemap.xml` вернули HTTP 200, но все три — одинаковый HTML главной, 1906 байт, с заголовком «Packerra.kz - упаковочные материалы в Алматы». На продакшене это ещё не рабочие robots/sitemap и серверный HTML нового решения. Проверки главной с тестовыми User-Agent Googlebot, Bingbot и OAI-SearchBot тоже вернули 200 без challenge; это результат обычных запросов из одной точки, не подтверждение доступа настоящих роботов с их IP.

Владелец сообщил, что сейчас нет доступа к Search Console, Bing Webmaster Tools и журналам Cloudflare. Без него не подтверждены владение сайтом, принятие sitemap, состояние индексации, реальная политика WAF/ботов и базовые поисковые показатели. Код не публиковался; этап целиком не завершён. После публикации и восстановления доступа выполнить действия подключения и проверки, описанные в README. Политика GPTBot не менялась, llms.txt и дополнительные системы аналитики не добавлялись.

Проверено: пять связанных тестов, включая обновление карты после операций API в отдельной тестовой БД, обе production-сборки и итоговый diff. Локальный sitemap прошёл строгий XML-парсер: 123 уникальных URL, 19 800 байт, ссылки языковых альтернатив присутствуют в карте. Шесть страниц из карты (главная, товар, категория, задача и доступные KK-версии) вернули HTTP 200 с серверным HTML; robots.txt содержит Sitemap, админка сохраняет noindex. Проверка кода существенных замечаний не выявила. Браузерные проверки и публикация не выполнялись.

Риски: правила Cloudflare/DNS требуют доступа владельца; SSR сложнее текущей SPA; кеш должен учитывать обновления коммерческих данных. Каждый этап реализуется и проверяется отдельно, следующие этапы не считаются разрешёнными к реализации автоматически.
